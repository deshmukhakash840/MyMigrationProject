Question. Why not use Page Factory model?

I've used PageFactory in the past, but I prefer Page Objects based on By locators and explicit waits. 
It provides better synchronization, avoids stale element issues, and aligns with modern Selenium framework design.

Question. What is TestContext class used? Why wasn't it used for sequential execution? 
			Why used for parallel execution? 
			If everything else is not kept as static then why TestContext threadlocal and methods are static?

TestContext is nothing but a POJO
Your listener needs to know: Which browser belongs to THIS thread? Which env belongs to THIS thread?
Listener doesn't have access to your BaseTest object. So we need somewhere central to store:
Thread 1 -> Chrome QA
Thread 2 -> Firefox Stage
That's what ThreadLocal TestContext does.
Summarizing : We use TestContext.getContext().getBrowser() and TestContext.getContext().getEnv() 
				throughout the framework to retrieve the browser and environment details. 
				These values are stored in a TestContext object that is maintained 
				separately for each thread using ThreadLocal, ensuring thread safety during parallel execution 
				while also working correctly for single-threaded execution.

If you don't use ThreadLocal for it then it can also be used for sequential execution.

Because we don't want to create objects of this class everywhere, we keep the methods static.
Static methods are fine here because: 'ThreadLocal holds the thread-specific data' not the static method itself.

Note: Earlier we used to have BaseTest variables browserName, environment. 
And all classes used to access the information by accessing these variables.
Now, we implemented a better approach. To have a POJO and getters to access information of browserName, environment.

Question. How does this framework ensure parallel execution?

To support parallel execution, I moved execution-specific data such as browser and environment 
into a ThreadLocal-backed TestContext. 
This prevents data collisions between parallel threads and provides a centralized way for listeners, reports, utilities, and tests 
to access execution context without relying on shared static variables.

Question. Which branch does GitHub execute?

Depends on your YAML.
---------------------------------------------
Example: 

YAML below- 
on:
  push:
    branches: [ main ]
    
    
    
    
means: 	Push to main
			↓
		Workflow runs
		
but:	Push to feature branch
				↓
		Nothing happens
---------------------------------------------
		
Now, If you configure: YAML below-
on:
  push:
    branches:
      - main
      - develop
      
      
then,
		Push to main
			↓
			Run
			
		Push to develop
			↓
			Run
---------------------------------------------

Also, if you use: YAML below-

on:
  pull_request:
    branches: [ main ]
    
    
    
then,

		feature branch
			↓
		Create PR into main
			↓
		Workflow runs
---------------------------------------------
		
Now, if you have both:

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]
    
then, 
		CI workflow executes when 	a) Pull Request Validation (runs the workflow against that merged code.)
									b) After Merge (runs the workflow on main branch)

Question. How are Soft Asserts different than Hard Asserts. Why does Soft Assert needs to be Thread Safe?
-> 	
Hard Assert = instant check

	Like a security guard: “Show me ID → OK / NOT OK → done”
	No memory retained.
	
Soft Assert = checklist

	Like a QA checklist:
		Check login ✔
		Check profile ✔
		Check logout ❌
	You must store all results until end.
	Now imagine 2 testers sharing one checklist → chaos.
	That’s why isolation is required.
		
Now the technical answer -> SoftAssert maintains internal state across multiple validations in a test. 
							In parallel execution, this state can be corrupted if shared between threads. 
							Hence we use ThreadLocal to isolate SoftAssert instances per test thread. 
							Hard Assert is stateless and executes independently, so it doesn't require thread safety.
